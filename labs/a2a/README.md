# A2A workshop rig

Working reference implementation behind the **A2A: Agents That Talk to Each
Other** training unit on the [Zenable Learning
Hub](https://www.zenable.app/learn?utm_source=github&utm_medium=labs_repo&utm_campaign=a2a_readme).
Every command and every expected output in that lab was captured from a real
run of this rig; `evidence/` holds the raw output.

The lab clones this tree and runs it, so these files are the ones a reader
executes. A fix here reaches them immediately; nothing is retyped from the
Learning Hub.

Fully open source: A2A Python SDK (Apache-2.0), Keycloak (Apache-2.0), uv,
Docker. No cloud account and no LLM key — the agents are deterministic lookup
tables, so the lab cannot fail on somebody's quota.

## Run it

```bash
docker compose up -d
./keycloak/bootstrap-realm.sh

cd agents && uv sync
uv run python forecast_agent.py &   # Agent A, :9001
uv run python planner_agent.py &    # Agent B, :9002
uv run python rogue_agent.py &      # impersonator, :9009

cd .. && ./scripts/capture-evidence.sh
```

## Participants

| Identity | Role |
|---|---|
| `agent-a-forecast` | Agent A's workload identity, used when it calls B |
| `agent-b-planner` | Agent B's workload identity, used when it calls A |
| `workshop-cli` | you at the terminal — a third participant, not a borrowed agent credential |
| `agent-c-stranger` | right audience, wrong permission — isolates the 403 |
| `agent-d-expiring` | 1-second tokens — isolates expiry |
| `impostor` (rogue-realm) | valid token from a second trust domain |

Each agent holds the scope for the agent it **calls**, never the scope it
enforces. An agent granted its own scope could mint tokens for itself, and
the audience check would prove nothing.

## Findings that changed the lab

These surfaced only by running it, and each is taught explicitly:

- **A2A 1.0 renamed the JSON-RPC methods.** `SendMessage`, not `message/send`.
  Practically every tutorial online still shows the 0.x form.
- **Raw HTTP callers must send `A2A-Version: 1.0`.** Without it the server
  assumes 0.3 and refuses. The SDK client sets it; curl does not.
- **`create_client` only applies `signature_verifier` when given a URL.** Pass
  a card you fetched yourself and verification is silently skipped — the
  argument is still accepted. This is a live footgun.
- **The SDK only attaches credentials when the card asks for them.** A rogue
  card that omits `securitySchemes` receives nothing; impersonating the
  security block is what makes a client hand over its token.
- **`a2a-sdk` 1.x types are protobuf, not Pydantic.** Cards are built with
  protobuf constructors and map fields, and serialize to camelCase.

## Layout

- `docker-compose.yml` — Keycloak 26.7.1, dev mode
- `keycloak/bootstrap-realm.sh` — realm, scopes, audience mappers, clients
- `agents/` — `forecast_agent.py` (A), `planner_agent.py` (B),
  `rogue_agent.py` (impersonator), `a2a_auth.py` (verification + client
  credentials), `card_signing.py` (JWS sign/verify), `a2a_client_util.py`
- `scripts/` — `get-token.sh`, `decode-jwt.py`, `negative-tests.sh`,
  `capture-evidence.sh`
- `evidence/` — captured output, regenerated by `capture-evidence.sh`
